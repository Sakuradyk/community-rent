# 前后端并行开发方案（垂直切片）

> **这份文件解决什么问题**：一个人 + AI 做前后端两个应用，怎么排才能「每完成一个功能就能打开网页自己点一遍」，同时不把返工堆到末期。
> **结论一句话**：不串行写完后端再写前端，也不水平并行（后端全写接口 / 前端全写页面），而是**按业务切片垂直并行**——每个切片：冻结契约 → 后端接口 → 前端页面 → 当切片联调 → 你可演示。
> **配套文件**：`PROJECT_RULES.md`（怎么做）、`社区物品租用平台-需求总结.md`（做什么、不做什么）、`项目进度.md`（做到哪了）。

---

## 1. 为什么不采用外部建议的原样方案

外部建议的方向（契约先行 → 并行 → 切片联调）是对的，但它给的三样具体内容与本项目不匹配，照抄会出事：

| 外部建议 | 本项目实际 | 处理 |
| :-- | :-- | :-- |
| 订单状态机「发布 → 预约申请 → 出租方审批 → **押金冻结** → 取货 → 归还 → **验收** → 押金退还 / 争议」 | 母版是**六状态**：`PENDING / CONFIRMED / IN_USE / OVERDUE / COMPLETED / CANCELLED`；**押金只做账面抵扣，不做冻结**；**没有"验收"独立环节**，归还即进入结算 | **只采纳其原则（先定状态机再定接口），不采纳其模型**。改状态机等于改论文立论，不在范围内（需求总结 §6、§10） |
| 用 Apifox / MSW 做 mock | §2.1 禁止擅自新增依赖；单人项目没有"另一方"协作成本，工具的收益兑现不了 | 用规则 F13 的 `src/mock/*.js` 静态桩 + `vite` 环境变量切换开关，**不引任何新依赖** |
| 「契约变更必须显式通知另一方」 | 没有另一方，但**同一份契约会同时体现在三个地方**：`docs/接口文档.md`、后端 DTO/VO、前端 `src/utils/constants.js` | 改成「三处同步 + 提交说明打 `CONTRACT CHANGE`」，比"通知"更可验证 |

**唯一必须照抄的一条**：契约要在写代码之前定，并且定的是**当前切片的契约**，不是全部 43 条 FR 的契约。一次性冻结全量 OpenAPI 在这个项目上做不到——K2 的 4090 明细、K3 的结算字段，要等真实算过一遍才知道长什么样，提前冻结只会冻结出错的形状。

## 2. 契约的三个真源（改一个必须改三个）

| 层 | 文件 | 内容 |
| :-- | :-- | :-- |
| 文档（人读） | `docs/接口文档.md` | 每个切片一节：URL / 方法 / 请求字段 / 响应字段 / 枚举 / 错误码 / 边界行为 |
| 后端（机读的契约） | `module/*/dto`、`module/*/vo` + `ErrorCode` | DTO/VO 字段名就是契约字段名，**前端不猜字段名，照文档抄** |
| 前端（唯一枚举来源） | `web-user/src/utils/constants.js`（admin 同构） | 状态枚举、错误码文案、限制值（分页上限、图片 5MB、日期格式） |

**切片 0 必须一次性钉死的四条格式**（这四条不一致，返工量最大）：

1. **分页**：入参 `pageNum`（从 1 起）/ `pageSize`（默认 10，上限 100）；响应 `{list,total,pageNum,pageSize}`。前端不做本地分页。
2. **主键**：所有 `Long` id 序列化为**字符串**（`"12"`），前端**禁止** `Number(id)`、禁止 `id + 1` 之类的算术。
3. **时间**：日期 `YYYY-MM-DD`，时刻 `YYYY-MM-DD HH:mm:ss`；前端传参只用 `dayjs().format('YYYY-MM-DD')`，禁止传 `Date` 对象、禁止传带时区的 ISO 串。
4. **金额**：JSON 里是数字（`25.00`），**只做展示**，前端一律 `Number(x).toFixed(2)`，**禁止**在前端加/乘/取整算钱（算钱只有 `/api/orders/quote` 一处出口，规则 F1）。

**4090 的 `data` 形状**（K2 的对外契约，现在就定，别等写完再补）：

```json
{
  "code": 4090,
  "message": "该时段已被占用，请选择其他日期",
  "data": {
    "itemId": "2",
    "conflictDates": ["2026-11-20", "2026-11-21"],
    "suggestRanges": [{ "startDate": "2026-11-24", "endDate": "2026-11-26" }]
  }
}
```

前端 F7 拿到 4090 就做两件事：日历上把 `conflictDates` 标红、把 `suggestRanges` 作为「试试这几天」按钮。**这个形状一改，日历组件就得重写**，所以它属于切片 0 的冻结内容。

## 4. 切片内的工作纪律

1. **一个切片只改一个模块的对外契约**。切片 3 不允许顺手改物品列表的返回结构。
2. **后端先出契约测试**，再出实现：新增 `XxxApiContractTest`（`MockMvc`），断言的是**字段名、枚举值、错误码**这些"前端会依赖的东西"，不是业务分支。业务正确性归 `XxxIntegrationTest`。两类测试职责不重叠。
3. **前端禁止猜字段**：页面里出现的字段名必须能在 `docs/接口文档.md` 当节找到，找不到就是契约没冻结，先补契约再写页面。
4. **Mock 只在"后端本切片未完成"时使用**：`web-user/src/mock/{slice}.js` 导出与契约同形的假数据，`request.js` 用 `import.meta.env.VITE_USE_MOCK` 切换；切片联调完成后**保留但默认关闭**，并在提交说明写「本切片已切真接口」。禁止用 mock 数据伪装功能已完成。
5. **契约变更三种写法**：加字段（向后兼容，双写三处）；改字段名/类型（不兼容，必须同一切片内改完前后端，提交说明首行打 `CONTRACT CHANGE:`）；删字段（先确认前端已不再引用）。
6. **每切片结束的 DoD**：G1 编译 → G2 全绿（含新增契约测试）→ G3 手工点通「可演示」那一列 → B 档提交 → `项目进度.md` 更新 + `docs/接口文档.md` 当节同步。

## 6. 现在就能做的一件事

后端 `/api/auth/register`、`/api/auth/login`、`/api/auth/refresh`、`/api/auth/logout`、`/api/users/me`、`/api/communities`、`/api/files/upload` **已经全部就绪并实测通过**（45 单测 + 7 条端到端）。也就是说**切片 1 不需要任何 mock**，骨架搭好当天就能在浏览器里真实注册、登录、上传头像。

所以推荐下一步不是"先设计全部接口"，而是：**切片 0（骨架 + 契约文档四条格式）→ 立刻接切片 1（账号页面）**，两天内你就能打开网页自己注册登录。
